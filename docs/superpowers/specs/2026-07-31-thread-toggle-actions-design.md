# 邮件状态双向切换修复设计

## 目标

修复本地邮箱前端中重要标记无法取消、归档无法恢复，以及操作成功后乐观状态长期覆盖真实数据的问题。

## 边界

- 不修改 Mail Core、数据库结构或服务端 API。
- 保留现有五秒撤销窗口。
- 操作成功后立即清理该操作自己的乐观记录。
- 同一类型的最后一个待处理操作完成后才刷新线程和邮箱统计。
- 重要标记菜单始终显示，并根据当前状态执行标记或取消标记。
- 归档按钮在 Inbox 中归档，在 Archive 中移回 Inbox。

## 数据流

1. 用户操作立即写入 Jotai 乐观状态。
2. 撤销窗口结束后调用本地邮箱 API。
3. API 成功后删除当前待处理记录和当前乐观记录。
4. 如果该类型已经没有其他待处理操作，则刷新真实线程和邮箱数据。
5. API 失败时移除当前乐观记录、刷新真实数据并显示失败提示。

## 测试

- 单个待处理操作完成后必须被清理，并要求刷新。
- 多个同类型操作完成一个时，只清理当前操作且不提前刷新。
- 最后一个同类型操作完成时要求刷新并清理类型集合。
- 重要菜单同时包含标记与取消标记文案。
- 归档目录中的归档按钮目标为 Inbox，其他目录目标为 Archive。
