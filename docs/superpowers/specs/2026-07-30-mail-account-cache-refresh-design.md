# 邮箱绑定后本地账户缓存刷新设计

## 问题

Nango 和手动 IMAP/SMTP 绑定成功后只刷新连接列表与默认连接，没有刷新
`mail.account.list`。如果页面在绑定前已经缓存了空账户列表，绑定后
`MailAccountProvider` 仍无法解析当前本地邮箱账户，保存草稿和发送邮件会在前端抛出
`MAIL_ACCOUNT_UNAVAILABLE`，请求不会进入后端。

数据库中的连接、本地邮箱账户和发件身份已经正确创建，因此本次不修改后端、数据库
或 Gmail 投递逻辑。

## 方案

新增一个前端公共刷新函数，接收 React Query 客户端及三个必需查询键：

- 连接列表；
- 默认连接；
- 本地邮箱账户列表。

函数统一失效并等待三组查询刷新完成。Nango 与手动 IMAP/SMTP 绑定成功后均调用该
函数，再关闭弹窗和通知上层。

选择公共函数而不是在两个弹窗中分别追加一行，是为了让三个查询键形成一个不可拆分的
绑定后刷新契约。不会清空全部前端缓存，也不会通过提高缓存版本掩盖状态失效问题。

## 错误边界

刷新失败时沿用现有绑定失败处理，不继续显示“连接成功”。邮箱账户未就绪时现有
`MAIL_ACCOUNT_UNAVAILABLE` 防线继续保留，防止以空 `accountId` 请求后端。

## 测试

使用真实 `QueryClient` 写回归测试：预置三组查询缓存，调用公共刷新函数，验证三组
查询均被标记失效。随后运行 Mail 应用相关单元测试和类型检查。
